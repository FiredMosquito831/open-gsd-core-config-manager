<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Filesystem (~/.gsd/defaults.json) → discovery.ts | Reading a user file that may be absent or contain secret-shaped values |
| Env (GSD_HOME) → path resolution | An attacker-controlled env var could redirect the global-defaults path (low risk: local single-user tool) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-InfoDisc-D | Information Disclosure | `readGlobalDefaults` error paths | medium | mitigate | On a parse/read error, log/throw with the file PATH only — never `JSON.stringify` or include the file body (which may hold secret-shaped fields like `brave_search`). ENOENT is handled silently as `{ found: false }`. |
| T-01-PathTrust | Tampering | `GSD_HOME` env redirect | low | accept | Single-user local tool; `GSD_HOME` is the same override gsd-core itself honors. discovery.ts accepts an already-resolved absolute path downstream (Config I/O does not trust arbitrary UI-supplied relative paths — that boundary is Phase 3's). Accepted. |
| T-01-SC | Tampering | node builtins only (no new deps) | low | accept | This plan adds no third-party dependency. |
</threat_model>
