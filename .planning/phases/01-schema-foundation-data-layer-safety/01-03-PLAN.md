<objective>
Build the Ajv 2020-12 validation layer (SAVE-01, success criterion #3) and the prototype-pollution-safe dot-path patch utility that the save pipeline depends on.

Two easy-to-get-wrong details are load-bearing here (RESEARCH.md § Decision: Ajv Setup, § Pitfall 2, § Pitfall 4): (1) the validator MUST import `Ajv2020` from `ajv/dist/2020` — the default `Ajv` export is draft-07 and silently mis-validates a 2020-12 schema; (2) the bundled schema's `x-*` vendor keywords must be registered via `ajv.addKeyword({ keyword })` rather than disabling strict mode wholesale, or `ajv.compile()` throws at startup. `additionalProperties` stays open everywhere (never `false` at the enforcement layer, RESEARCH § Pitfall 5) so a config with a key newer than the schema still validates and saves.

Purpose: The single server-side validation source of truth that actually protects the file, and the guarded mutation primitive for patch-in-place saves.
Output: `validate.ts`, `patch.ts`, and their unit tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Caller-supplied dot-path + value → in-memory config object | An attacker-influenced key path could target `__proto__`/`constructor`/`prototype` |
| Raw config object → Ajv validation / error rendering | Secret-shaped field values could leak into error messages/logs |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-Proto | Tampering | `safeSet()` in patch.ts | high | mitigate | Explicit `FORBIDDEN_SEGMENTS` denylist rejecting `__proto__`/`constructor`/`prototype` as ANY path segment; unit test proves a `__proto__` payload is rejected and no global pollution occurs (RESEARCH § Security Domain). |
| T-01-InfoDisc | Information Disclosure | `validate()` / `formatErrors()` error paths | medium | mitigate | Error rendering emits only `instancePath` + `keyword`; never `JSON.stringify` the whole config or include the offending value. Unit test asserts a secret-shaped value never appears in rendered error text. |
| T-01-OverStrict | Denial of Service (self-inflicted) | Ajv enforcement schema | medium | mitigate | `additionalProperties` stays open everywhere; unknown/future keys validate rather than block saves (RESEARCH § Pitfall 5). Test proves an unknown-key config returns valid. |
| T-01-SC | Tampering | ajv / ajv-formats (already installed in Plan 01) | high | accept | Cleared `OK` by RESEARCH § Package Legitimacy Audit; versions pinned exactly in Plan 01. |
</threat_model>
