<objective>
Assemble the read side of the data layer: `load(projectConfigPath)` reads the raw project config, locates + reads the global defaults, computes the layered EffectiveTree with provenance, and produces the flat unknown-key bucket — returning the frozen `LoadResult` (DISC-06 + SAVE-03).

The unknown-key detection is the SAVE-03 / success-criterion-#1 foundation (RESEARCH.md § Decision: Effective-Value / Provenance Contract, point 3): flatten EVERY leaf path in the raw object and classify each against the reconciled known-key set (exact keys ∪ dynamic patterns), so an unknown key nested inside an otherwise-recognized namespace (e.g. a future `workflow.some_toggle`) is still caught — not just unrecognized top-level namespaces. The raw project object is returned unmodified so the Plan 06/07 patch-in-place save never rebuilds from schema (RESEARCH § Pitfall 1).

Purpose: The single `load()` entry point that Phase 2's server will call, producing the frozen load contract.
Output: `known-keys.ts`, `load.ts`, and `load.test.ts`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Filesystem (project config + global defaults) → load() | Reading two JSON files that may contain secret-shaped values or be malformed |
| Raw config object → returned LoadResult | The original object must not be mutated (SAVE-03 patch-in-place invariant depends on it) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-InfoDisc-L | Information Disclosure | load() error paths (parse failures) | medium | mitigate | On a JSON parse error, throw/log with the file path + a static message only; never `JSON.stringify` the raw object or echo file contents (may hold `brave_search`/`firecrawl` secrets). RESEARCH § Security Domain. |
| T-01-KeyDrop | Tampering | unknown-key flattening in load() | high | mitigate | Flatten EVERY leaf path (including nested-in-known-namespace) and classify; any non-known key is surfaced in `unknown[]`, never dropped. Test proves fabricated + drift keys land in the bucket (SAVE-03). |
| T-01-Mutate | Tampering | raw.project reference | high | mitigate | load() returns the original parsed object without in-place normalization; test proves no mutation across loads (protects the patch-in-place save from key loss). |
| T-01-SC | Tampering | no new deps | low | accept | Composes Plan 01-04 code + node builtins only. |
</threat_model>
