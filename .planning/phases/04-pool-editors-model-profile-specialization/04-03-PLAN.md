| Boundary | Description |
|---|---|
| user interactions → project draft callback | Selected entries and map keys arrive as user-controlled browser input. |
| focused components → ConfigEditor | Editors must not bypass full-candidate validation or the secured save API. |
| unsupported config child → UI | Future/unknown map children could be lost if treated as ordinary editable entries. |

| ASVS-04-03-V4 | V4 Access Control | focused components → save boundary | `ConfigEditor`/`SaveBar` remain the sole save owner; components receive callbacks only and add no API/path access. |

| ASVS-04-03-V7 | V7 Error Handling | validation error → UI | Field/list errors are path-oriented, retain the invalid draft, and block save without exposing candidate data. |
| ASVS-04-03-V13 | V13 API/Web Service | client assumption → existing local API | No specialized endpoint is introduced; existing token/origin/opaque-id API contract is reused through `ConfigEditor`. |
