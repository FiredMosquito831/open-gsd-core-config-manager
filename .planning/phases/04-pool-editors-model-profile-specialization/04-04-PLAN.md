<threat_model>
## Trust Boundaries
| Boundary | Description |
|---|---|
| profile/catalog data → browser editor | Catalog-derived profile choices can otherwise be mistaken for arbitrary user identity data. |
| changed draft paths → post-save notice | Notice derivation must not expose changed values or make unverified runtime claims. |
| ConfigEditor candidate → existing local API | Profile/pool edits must retain token, origin, opaque-id, validation, atomicity, and snapshot safeguards. |

| T-04-11 | Information disclosure | RuntimeInstallNotice | medium | mitigate | Task 2 derives static labels from metadata and changed paths, never values/server strings, and tests value-free output. |
| T-04-12 | Spoofing/Tampering | ConfigEditor save integration | high | mitigate | Task 2 retains existing opaque-id/token/origin-protected API and asserts full candidate safe-save behavior. |
| T-04-SC | Tampering | npm installs | high | mitigate | No install task occurs; no additional profile, DnD, or UI library is introduced. |
</threat_model>
