<bundling_reality_check>
**This corrects 02-RESEARCH.md Pitfall 4 and its tsup example. Read before writing the config.**

02-RESEARCH.md warns that tsup will externalize workspace-local packages and prescribes `noExternal: ['@gsd-config-manager/config-io', '@gsd-config-manager/server']`. **Those package names do not exist.** This repo has no npm workspaces and no per-package `package.json` — `packages/config-io`, `packages/server`, and `packages/cli` are plain source directories imported by **relative path** (see any `test/config-io/*.test.ts` and every Phase 2 import).

Consequences:
- Relative imports are inlined by esbuild automatically. There is nothing to add to `noExternal`, and adding an entry for a non-existent package name is at best a dead config line and at worst a misleading one. Do not add it.
- tsup's default externalization of `package.json` `dependencies` (fastify, commander, open, env-paths, ajv, proper-lockfile, write-file-atomic) is exactly right: they are real npm packages that npm installs alongside the published package.
- `packages/schema-data/bundled-schema.json` is inlined via the JSON module import in `packages/server/src/schema.ts` (Plan 05), so it needs no entry in `files`. Task 3's extracted-tarball run is what proves that.

The real bundling risk here is not externalization — it is **build order**. `tsup` cleans `dist/`. If it runs after `build:client`, it deletes `dist/client`. That is the bug that ships a blank page to every `npx` user, and Task 2 orders the scripts to prevent it.
</bundling_reality_check>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Repo working tree → published npm tarball | Anything included ships to every user; anything omitted breaks every user. Both directions are security-relevant. |
| Published tarball → end-user machine via `npx` | The tool executes with the user's full filesystem privileges on a machine the author never sees. |
| Process termination (Ctrl-C, terminal close, Task Manager) → OS resources | An unclean exit leaves a bound port or a stale advisory lock that blocks the user's next save. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-10 | Tampering | `package.json` `files` / build order — a stale or missing `dist/client`, or a `packages/**` source that failed to inline, shipping a broken tool to every `npx` user | medium | mitigate | `prepublishOnly` rebuilds immediately before packing (Pitfall 5); the build order runs tsup's full `dist/` clean before the scoped `dist/client` copy; `tarball-contents.test.ts` asserts both artifacts appear in `npm pack --dry-run --json`; and Task 3 extracts the real tarball outside the repo and runs it, which is the only check that catches an unresolvable import. |
| T-02-32 | Information Disclosure | The tarball shipping source, tests, `.planning/` artifacts, or `node_modules` — leaking internal planning content and bloating every install | medium | mitigate | An explicit `files` allowlist (`dist/cli.js`, `dist/client/**`) rather than an `.npmignore` denylist; `tarball-contents.test.ts` asserts no packed path starts with `packages/`, `test/`, `.planning/`, `web/`, or `scripts/`. |
| T-02-33 | Tampering | Publishing a bundle built from a different (stale) source tree than the committed one, so the shipped behavior does not match the audited code | medium | mitigate | `prepublishOnly` runs the full build from source; `dist/` is git-ignored so a stale committed artifact cannot be published by accident. |
| T-02-09b | Denial of Service | Windows-specific signal-delivery divergence: a real console Ctrl-C behaving differently from the emulated `kill('SIGINT')` the automated suite sends, leaving a bound port or a stale `proper-lockfile` lock | medium | mitigate | Task 4 is a blocking human checkpoint executing a physical Ctrl-C in a real Windows terminal and verifying the port is released (`netstat`) and no `.lock` remains — 02-VALIDATION.md's designated Manual-Only verification for DIST-04. |

A hard kill cannot be intercepted, and building a separate stale-lock reaper is disproportionate for a single-user local tool with an existing 10-second stale window. |
| T-02-35 | Tampering | An unpinned or floated dependency entering the published tarball's dependency tree | medium | mitigate | Every dependency is an exact pin (Plan 01, asserted programmatically) and `package-lock.json` is committed; this task re-asserts `write-file-atomic` is still `7.0.1`. |
