<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| App-data override → server process | Persisted external state may be corrupt, stale, or maliciously edited. |
| Proposal → active snapshot | Candidate schema crosses into authoritative validation/rendering. |
| Durable store → in-memory authority | Crash ordering must not split persisted and active generations. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-03-01 | Tampering | persisted override | critical | mitigate | Validate envelope, identity, normalize, and compile on every load; quarantine/ignore invalid state and fall back. |
| T-06-03-02 | Denial of Service | startup manager creation | high | mitigate | Catch override failures and start with compiled bundled baseline plus persistent warning. |
| T-06-03-03 | Tampering | activation ordering | critical | mitigate | Compile first, atomically persist one envelope, then perform one reference swap; retain old snapshot on failure. |
| T-06-03-04 | Spoofing | version precedence | high | mitigate | Compare stable semver and immutable identities; reject conflicting same-version provenance. |
| T-06-03-05 | Information Disclosure | warning/status | medium | mitigate | Expose static path-free warning; keep raw errors in injected server warning sink only. |
| T-06-03-06 | Elevation of Privilege | persisted schema | high | mitigate | Treat persisted descriptors as data and compile only through existing Ajv pipeline; never module-load metadata. |
| T-06-03-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package installation occurs in this plan. |
</threat_model>
