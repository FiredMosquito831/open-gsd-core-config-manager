# Phase 6 — UI Design Contract

> Visual and interaction contract for the app-wide schema-maintenance workspace. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — retain the established project-owned CSS/component system |
| Preset | not applicable; `components.json` is absent and Phase 3/5 already establish the manual UI system |
| Component library | project-owned semantic React components; native controls and existing inert dialog pattern |
| Icon library | existing inline SVG icons only; add an inline 16px refresh/schema-status icon if needed, not a new dependency |
| Font | `Inter, ui-sans-serif, system-ui, -apple-system, BlinkMacSystemFont, sans-serif`; existing monospace stack for immutable identity, key paths, and hashes |

**Established visual tokens to reuse:** light/dark adaptive `--gsd-*` tokens in `web/src/styles.css`: background `--gsd-bg`, secondary surface `--gsd-surface`, elevated surface `--gsd-surface-elevated`, borders, text, muted text, accent, warning, success, and danger. Use existing radii (`6px` small, `10px` default) and shadows. Do not initialize shadcn or introduce a registry in this phase: that would create a second component system for one workspace.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps; evidence-row metadata separation |
| sm | 8px | Badge groups, compact row padding, adjacent controls |
| md | 16px | Default control/section internal padding; header/action separation |
| lg | 24px | Workspace section gaps, desktop pane gutters, review-card padding |
| xl | 32px | Major workspace section separation |
| 2xl | 48px | Empty/error state vertical breathing room |
| 3xl | 64px | Not required within the normal workspace; reserve for page-scale empty state only |

Exceptions: all pointer-operable controls, including the rail status control, refresh, filter, disclosure, retry, activate, cancel, and reset controls, have a **44px minimum hit target**. Existing `Button` spacing/variants remain the implementation baseline.

## Typography

Use only the two established weights: regular **400** and semibold **600**. Do not add bold/medium variants for this phase.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Metadata / badge / key evidence | 12px | 400 | 1.5 |
| Body / controls / explanatory copy | 14px | 400 | 1.5 |
| Section heading / result count | 16px | 600 | 1.2 |
| Workspace heading | 20px | 600 | 1.2 |

Use 12px monospace for release version, commit prefix, archive digest prefix, dates where compact, and schema key paths. Never rely on color alone for source, lifecycle, or warning status.

| Role | Value | Usage |
|------|-------|-------|

Accent reserved for: active source/status affordance; the primary fetch and activation CTAs; active filter/disclosure selection; changed-key markers; focus-visible outlines. It is not a general decoration color and is not used for deprecated, failed, or reset states.

## Workspace and Layout Contract

### Entry and persistent status

- Add one compact, persistent **schema status control** to the app shell utility/rail area. It remains available in ordinary editor and history views and opens the schema workspace.
- The control always communicates, in text plus a visual badge: active source (**Bundled** or **Refreshed**), the active `gsd-core` version, and the relevant accepted/refreshed date. Example compact label: `Bundled · gsd-core v1.7.0`; its accessible name includes the source, full version, date, and “Open schema maintenance”.
- Surface a startup fallback/corrupt-override condition as a persistent warning badge adjacent to this control. The warning remains until the user opens the workspace and resets or a valid refreshed schema is activated; do not use a transient toast as the only notice.
- Status is app-wide, never attached to the selected configuration. The control must remain usable when no tracked config is selected.

### App shell behavior

- Extend `workspaceMode` with `schema`. In schema mode, retain the tracked-config sidebar for orientation; hide the chapter navigation, global settings search, config editor save bar, and selected-config-specific heading.
- Main landmark label is **Schema maintenance**. Include a visible **Back to editor** secondary action; returning preserves the current selected config and ordinary editor context.
- Desktop at greater than 900px: retain the shell rail and tracked-config sidebar, then render the schema workspace as a single scrollable main column with a `max-width: 1100px`. The proposal review is a two-column layout: a 280–320px sticky summary/filter pane and a flexible evidence pane.
- Between 769px and 900px: main workspace is a single column; summary/filter pane becomes a full-width block above evidence.
- At 768px and below: existing rail/mobile sidebar behavior applies. Schema workspace is one column; header and action groups wrap/stack; every key, version, identity, and evidence value wraps at word boundaries rather than forcing horizontal page scroll. Evidence remains horizontally scrollable only inside a code/value comparison box.

### Workspace header and source panel

- Header eyebrow: `Schema maintenance`.
- Heading: `Keep your schema aligned with gsd-core`.
- Introductory body: `Check the latest stable gsd-core release, review the proposed changes, then choose whether to activate the validated schema.`
- Show an elevated source/status card immediately below the header. It contains active source, version, last activated/refreshed time, last checked time (if present), immutable commit prefix, and archive digest prefix when available. Reveal full immutable identifiers through an in-place disclosure/copy-safe text field; do not expose URLs, app-data paths, archive paths, raw parser output, or raw server errors.
- Default action in idle state is primary **Check for updates**. Supplement with a concise trust note: `The helper checks the latest stable release and reads allowlisted data only. It never runs remote code.`

### Staged workflow

1. **Idle / status:** Show the active schema source card, status timestamps, primary **Check for updates**, and secondary/destructive reset area when active source is Refreshed.
2. **Checking and reconciling:** Replace the primary action with disabled `Checking latest stable release…`; show a determinate stage list, not a fake percentage: `Checking release`, `Fetching pinned archive`, `Validating sources`, `Preparing review`. The active schema remains explicitly labeled `Still active` throughout. Disable refresh, activate, reset, and navigation actions that could replace the proposal; **Back to editor** remains available and does not cancel the server operation. Respect reduced-motion preferences: no looping/indeterminate decorative animation.
3. **Proposal ready:** Show the source identity card for the proposed stable release and the review summary/evidence described below. The proposal is visually labeled `Review required — not active` and includes the message `Nothing changes until you activate this proposal.`
4. **No semantic changes:** Replace review with a success state: heading `Your schema is up to date`; body `Checked gsd-core {version} on {check time}. No semantic schema changes were found, so your active schema was left unchanged.` Do not show **Activate schema**. The server-provided last-checked time updates separately from last activated/refreshed time.
5. **Failure:** Show a non-destructive alert: heading `Couldn’t prepare a schema update`; body `Your current schema is still active. Check your connection and try again.` Provide **Try again**. Render only static, path-free server-approved detail if available; never interpolate local paths, URLs, archive entry names, raw parse output, hashes beyond approved identity metadata, or exception text.
6. **Activated:** After successful activation, return to the idle/source card with source `Refreshed`, its accepted date, and new version. Announce via a `role="status"` live region: `Schema version {version} is now active. Editor fields and validation were refreshed.` Invalidate/reload the active schema and current config before editor mode resumes.
7. **Activation failure:** Show a non-destructive alert with heading `Couldn’t activate this schema update`, body `Your current schema is still active. Try activating the validated proposal again.`, and action **Try activation again**. Keep the validated proposal available for retry; do not claim activation succeeded or alter the active schema status.
8. **Reset failure:** Show a non-destructive alert with heading `Couldn’t reset to the bundled schema`, body `Your current schema is still active. Try resetting to the bundled schema again.`, and action **Try reset again**. Keep the reset recovery section available; do not claim reset succeeded or alter the active schema status.
9. **Cancelled:** **Cancel review** discards only the inert in-memory proposal, returns to idle, and announces `Schema update review cancelled. Your active schema was not changed.` It never reverts or changes the active schema.

## Change Review Contract

### Summary and filters

- Put a review heading `Review schema changes` above a count summary. Counts use these exact singular/plural labels: `{n} added`, `{n} changed`, `{n} deprecated`, `{n} documentation note(s)`.
- Render each nonzero class as a selectable count filter; default to **All changes**. Filters never alter candidate contents or provide partial activation. A visible sentence states: `Activation applies the complete validated proposal.`
- Display the proposal target as `Latest stable: gsd-core {version}` and source identity beneath it. Do not offer version/channel/ref selection.
- If all structural counts are zero but documentation drift exists, use the up-to-date structural state plus a warning note: `Upstream documentation changed for {n} key(s). Your curated explanations stay unchanged.` This is not activatable unless the server reports another semantic change.

### Grouped change rows

- Group evidence in this fixed order: **Added**, **Changed**, **Deprecated**, **Documentation notes**. Omit zero-count groups from the evidence pane while retaining zero values in the summary.
- Each group is a semantic `section` with its own heading and count. Each key is a 44px-minimum disclosure button containing: lifecycle marker/icon, full dot-path key, concise change summary, and the category if available.
- Lifecycle labels are text-first: `Added`, `Changed`, `Deprecated`, and `Documentation note`. Add a short visual marker but never encode the class only through color.
- Long dot paths wrap after separators on narrow screens; never ellipsize the only key identifier. Card summaries may be two-line clamped on desktop only when the full summary remains available on expansion.
- Expanded evidence shows only normalized server-provided before/after values for the fields that changed: presence, type, allowed options, default, dynamic/pattern shape, lifecycle/deprecation evidence, and/or documentation fingerprint status. Use a definition-list or two-column comparison with explicit `Previous` and `Proposed` labels. Preserve source-curated prose as a separate read-only statement: `Curated explanation retained.`
- For documentation drift, evidence states: `Upstream documentation changed. The curated explanation remains active and was not overwritten.` Never render upstream prose as a replacement or offer an edit/merge action.
- For deprecated keys, evidence states: `No longer present in gsd-core {version}. Kept as deprecated so older configs remain understood.` Include the source version evidence. Do not imply that the key will be removed from an existing config.

### Activation and reset actions

- Proposal review footer is sticky within the evidence pane on desktop and normal flow on compact/stacked layouts. It contains primary **Activate schema** and secondary **Cancel review**.
- **Activate schema** is enabled only for a server-confirmed, validated proposal. Clicking starts the activation request, disables both proposal actions, and changes its label to `Activating schema…`. No additional confirmation dialog is needed: the review surface already names the exact all-or-nothing action and it never touches tracked configs.
- Expose **Reset to bundled schema** only when a refreshed override is active or a persisted override warning requires recovery. It is a danger-styled button in a separately bordered recovery section, never adjacent to the primary activation CTA.
- Reset opens the established project-owned alert dialog. Initial focus is **Keep current schema**, Escape closes it, focus stays trapped while open, and focus returns to the reset button on close. Confirmation copy is fixed below. During reset, disable dialog actions and use `Resetting schema…`. On success, announce the bundled schema version and invalidate/reload schema plus current config queries atomically.

## Accessibility and Interaction Rules

- Use semantic landmarks: app shell rail, tracked-config `aside`, schema-maintenance `main`, review summary `aside` on desktop, grouped evidence `section`s, and disclosure buttons with `aria-expanded`/`aria-controls`.
- Use a `role="status"` live region for check stage, no-change, activation, cancellation, and reset success. Use `role="alert"` only for refresh failures, activation/reset mutation failures, and persistent fallback/corruption warnings.
- Focus behavior: opening schema maintenance moves focus to the `h1`; after **Check for updates**, retain focus on the action while its accessible label conveys progress; proposal readiness moves focus to `Review schema changes`; reset dialog initial focus is **Keep current schema** and closing it returns focus to reset. Do not steal focus for background status changes.
- All controls support keyboard activation. Expanded change disclosures operate with Enter/Space; preserve their expanded state while changing filters if the key remains visible, otherwise move focus to the resulting group heading.
- Every control has visible `:focus-visible` accent outline with 2px width and 2px offset, matching Phase 5.
- Status badges must meet text contrast and include a text label. Do not signal active/refreshed, deprecated, warning, success, or changed states by color or icon alone.
- Immutable source identity can be copied/selectable but not edited. Sensitive/local filesystem data is never presented in this workspace.
