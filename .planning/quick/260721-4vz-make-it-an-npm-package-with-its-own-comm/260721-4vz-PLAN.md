<objective>
Add `gsd-config-editor` as a second `bin` command alias mapping to the SAME shipped `./dist/cli.js`, keeping the existing `gsd-config-manager` bin byte-unchanged (locked user decision).

Purpose: The package, the 127.0.0.1 loopback server, the auto-opened browser, and the launch banner that prints the port/link ALL already exist and already work — `bootstrap.ts` does `app.listen({ port, host: '127.0.0.1' })` then `open(url)` (guard-wrapped so a headless/WSL failure prints the manual-open URL instead of crashing), `output.ts` `banner(url)` prints `Local:   http://127.0.0.1:<port>/?t=<token>` with the bold+cyan accent reserved for that URL line, and `--no-open` disables the browser-open path. The ONLY required delta is a second `bin` entry so the tool is invokable under the `gsd-config-editor` command name as well. This advances DIST-01 (single-command launch) and DIST-03 (public npm package with bundled UI), and makes installer/social references to `gsd-config-editor` resolve to the identical shipped artifact.

Output: (1) one-line addition to `package.json`'s `bin` object; (2) one new guard `it` in the packaging test; (3) automated verification that the ordinary suite still passes and the shipped CLI still prints the launch banner.

Note on `npx` resolution (recorded only, out of scope): the alias is fully invokable as `gsd-config-editor` once the package is installed (global or local bins on PATH) or via `npm exec`. Ad-hoc `npx gsd-config-editor` with no prior install resolves by package NAME, and renaming the package to match is explicitly FORBIDDEN by the locked decision, so that ad-hoc form is intentionally not covered here. `npm i -g gsd-config-manager` registers both command names equally; `npx gsd-config-manager` continues to work for everyone as before.
</objective>
