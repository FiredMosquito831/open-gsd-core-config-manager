Evidence: project resolution is inherit, installed role files contain sonnet/opus, and session logs show Codex rejecting those aliases.

Interpretation: native Codex agent definitions were generated with Claude-tier aliases and were not regenerated after switching to inherit.

### Runtime identity mismatch — Confidence: HIGH

Evidence: GSD init reports agent_runtime: claude in the Codex session. Runtime-aware non-Claude resolution therefore was not active.

## Root Cause

The primary root cause was a broken Codex adapter boundary: GSD correctly resolved inherit, but native Codex dispatch consumed stale generated agent TOMLs containing Claude-only sonnet/opus aliases and fixed reasoning efforts. The runtime was also identified as claude, so the non-Claude omit-model/inherit path was not active.

A secondary orchestration defect worsened the incident: the caller did not use the configured effort map and manually passed high, xhigh, and low; after typed failures it switched to generic agents, bypassing typed GSD enforcement.

## Recommended Actions

1. Fix Codex installation/sync so generated Codex agent TOMLs contain no Claude aliases when the effective profile is inherit; omit model and let Codex inherit the parent model.
2. Propagate runtime identity as codex before init/model resolution, or make the Codex adapter unconditionally use Codex runtime semantics.
3. Add a health check that validates installed model and reasoning metadata against current resolution, not just file existence.
4. Add a Codex-specific TOML effort sync path, or resolve effort at spawn time.
5. Pass resolved efforts (researcher low, planner medium, checker medium); never substitute ad-hoc values during recovery.
6. Close completed handles before retrying/spawning checkers to avoid thread-limit masking.
7. Add a Codex smoke test for one native researcher and planner under model_profile inherit.
