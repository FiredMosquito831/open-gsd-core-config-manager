agent_skills

object

Assigns skill sets to specific agent types, extending what individual agents know how to do. Each key is an agent type (e.g. gsd-executor) and each value is either a single skill-set path string (e.g. skills/review) or an array of skill-set paths to assign multiple skill sets to one agent type. Use this to give particular agents extra domain or workflow skills without changing the global skill configuration.

capabilities.auto_update

boolean

Controls whether installed third-party capabilities are allowed to auto-update to newer versions. Off by default, so capabilities stay at their installed version until you explicitly update them. Even when you turn this on, GSD re-prompts for explicit consent whenever a new version changes its executable surface (hooks, command modules, or MCP servers) compared to what's installed — the consent you gave was for a specific surface, not a blank cheque for future changes. Enable this when you want capabilities to update freely within the same surface; leave it off when you want to approve every update manually.

DEFAULT false Capabilities

capabilities.strict_known_registries

array · null

Controls where GSD is allowed to install third-party capabilities from, acting as a supply-chain trust gate. When null or unset (the default), installs from any external source are allowed — the normal consent prompt still applies. An empty array [] is lockdown: all external installs are blocked and only local-path installs are permitted. An array of hosts like ["github.com", "npm"] is an allowlist — only those source hosts are permitted, and matching is host-based (so a lookalike like evilgithub.com is rejected even when github.com is allowed). A malformed value fails closed (install refused). Set this to lock down capability installs on shared or sensitive machines.

Sets the timeout in milliseconds for parallel subagent tasks such as codebase mapping. If a subagent takes longer than this, GSD stops it and reports a timeout. Increase this for very large codebases or slower models; the default of 300000 (5 minutes) fits most projects.

DEFAULT 300000 Workflow

workflow.tdd_mode

boolean

Enables test-driven-development mode for eligible tasks. When on, the planner annotates qualifying tasks with type:tdd, and the executor enforces the RED/GREEN/REFRACTOR gate sequence: write a failing test first, make it pass, then refactor. Turn this on when you want TDD discipline applied automatically, and off when you want the planner to choose its own task types.

DEFAULT false Workflow

workflow.ui_phase

boolean

Enables the UI design-contract gate during planning for frontend phases. When on, /gsd-plan-phase generates a UI-SPEC.md that captures the visual and interaction contract before implementation begins, so the UI has an agreed-upon design to build against. Turn it off for backend-only projects or phases that have no user interface.

DEFAULT true Workflow

workflow.ui_review

boolean

Enables the retrospective UI audit against implemented frontend code. When on, GSD runs a structured visual and behavioral audit of finished UI work against its UI-SPEC.md contract, catching layout, accessibility, and interaction drift. Turn it off if your project has no UI or you perform UI reviews through another tool.

DEFAULT true Workflow

workflow.ui_safety_gate

boolean

Blocks planning/execution when a UI-SPEC contract is unmet. Unlike workflow.ui_phase (which generates the spec), this key is the enforcement gate: when on, failing to satisfy the UI-SPEC.md prevents the phase from sealing. With both keys on, GSD generates the contract and enforces it — the intended default. Setting ui_phase:true and ui_safety_gate:false generates a spec in pipelines but does not block manual planning.

DEFAULT true Workflow

workflow.verifier

boolean

When true, GSD runs a verifier agent after execution to check that the phase's deliverables match its plan and acceptance criteria. It is one of the core quality gates that catches drift between what was planned and what was built. Keep it on unless you intentionally want no automated post-execution verification.

DEFAULT true Workflow

workflow.windows_enforce

boolean

Enables the blocking ship-pre gate for the broken-windows ledger (.planning/WINDOWS.md). When true, /gsd-ship blocks while the ledger has any open entry, forcing the team to disposition each tracked deviation before shipping. When false (the default), windows are still tracked — the executor and verifier populate the ledger — but ship does not block, letting teams adopt tracking first and enforce later.

DEFAULT false Workflow
