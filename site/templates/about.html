About & security

A local-first tool for a local file. The security model is deliberately small enough to audit: bind loopback, check who is asking, never phone home.

01 / PURPOSE

Understand the setting before you change it.

GSD's config.json is powerful but opaque. The Config Manager exists to close that gap: every key gets a plain-language explanation, every enumerated value gets a meaning, and every edit is validated before it reaches disk.

The reference on this site is generated from the same canonical schema the editor uses. It is not a separate hand-maintained document that can drift.

The host can be Windows, macOS or Linux. A single npx command starts a helper on loopback, serves a bundled web UI, and opens your browser. There is no hosted service, no account, and no build step on your machine.

The project is independent and MIT licensed. Upstream GSD lives at open-gsd/gsd-core; this tool is not affiliated with it.

02 / BOUNDARY

The security model, in four layers.

01

Loopback binding

The server listens on 127.0.0.1 and nothing else. The host is a literal in the source; no flag or environment variable can widen it.

02

Host allowlist

Every API route checks the request Host against an allowlist, the standard defense against DNS rebinding — a remote page cannot make your browser treat its own hostname as this server.

03

Exact Origin guard

API routes require an exact-string Origin match against the sealed launch origin. A random local port plus an origin check blocks cross-origin calls from other tabs.

04

No remote code

The schema-update check is user-triggered, reads allowlisted release metadata, and never executes anything it downloads. It can propose a schema; you activate it.

04 / HARDENING

Details that matter for a file-editing tool.

  • Prototype-pollution guard. Dot-path patches reject __proto__, constructor and prototype at every segment.
  • Value-free errors. Validation and snapshot errors carry paths, keywords and codes — never the offending value, which could be a secret.
  • Sensitive-field flags. The schema marks API-key and provider keys as sensitive; the UI renders them masked.
  • Snapshot path isolation. Snapshot directories are derived from app data plus a hash of the config path, never from the config's own folder.
  • Revision-checked restores. Restores are writes with an expected revision, so they cannot silently clobber a newer file.
  • No token handshake. A per-launch URL token was removed by design; the boundary is loopback plus Host and Origin checks. See the changelog for that decision.
