<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User-entered path text to browser state | Path strings are untrusted until server validation. |
| Browser UI to workspace API | Add/scan/create actions can mutate tracked-list state. |
| Missing-file state to user actions | Locate/remove actions must not imply file deletion or unsafe writes. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-12 | Spoofing | file picker affordance | medium | mitigate | Never submit browser fake paths; explain limitation and require server-valid path flow. |
| T-03-13 | Tampering | scan review UI | medium | mitigate | Scan returns candidates only; user confirms selected paths before track calls. |
| T-03-14 | Information Disclosure | path display | low | accept | Displaying already-validated absolute paths is product-required local UX; rejected paths are not echoed by server errors. |
| T-03-15 | Tampering | remove tracked item | medium | mitigate | Remove only deletes workspace metadata, never filesystem files. |
</threat_model>
