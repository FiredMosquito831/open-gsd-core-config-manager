# Phase 2 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** Phase 2 (per its CONTEXT.md) builds no browser screens — "No UI screens are built here... Phase 3 builds the schema-driven UI." The bundled Vite/React frontend does not exist yet in this repo (no `components.json`, no Tailwind config, no `.tsx` files found). This phase's only user-facing surface is the **CLI/terminal output**: the `npx` launch banner, the "server running at `<url>`" line, port-in-use/startup error messages, the Ctrl-C shutdown confirmation, the browser-open fallback text, and the non-fatal snapshot-warning line (D-12). This UI-SPEC is therefore scoped to a **CLI output contract** — the six checker dimensions below are reinterpreted for terminal text rather than web UI, as instructed. The shadcn initialization gate is **not applicable** this phase (Phase 3 runs it when the real web UI is built).

## Output Structure ("Spacing Scale" — reinterpreted for terminal layout)

Declared conventions for vertical/horizontal structure of CLI output:

| Token | Value | Usage |
|-------|-------|-------|
| Leading blank line | 1 line | Printed before the shutdown block (D-03/Pattern 5), separating it from the shell's own `^C` echo |
| Indent | 2 spaces | Nested detail lines under a heading (the `➜ Local:` URL line, hint lines) |
| Section break | 1 blank line | Between the banner title and its detail lines is none (tight group); between distinct message *blocks* (e.g. banner vs. a later warning) is 1 blank line |
| Trailing punctuation | none | CLI lines never end with a period unless the sentence has an internal clause; keeps lines scannable |

Exceptions: none.

---

## Text Styling ("Typography" — reinterpreted as terminal emphasis conventions)

Exactly 2 weights and 1 accent color are used (no size scale exists in a terminal):

| Role | Style | Usage |
|------|-------|-------|
| Banner title | bold | "GSD Config Manager" title line only, printed once at successful startup |
| Body | normal weight, default terminal color | Standard message lines (hints, confirmations, descriptions) |
| Hint / secondary | dim | Secondary help lines: "Press Ctrl+C to stop", "Try again without `--port`…" |
| Emphasis (the URL) | bold + cyan | The one printed, copyable/clickable URL — see Color below |

Symbols (terminal equivalent of an icon library — no package added, hand-written Unicode):

| Symbol | Meaning | ASCII fallback (legacy `cmd.exe` / non-UTF8 consoles) |
|--------|---------|--------------------------------------------------------|
| `✓` | Success / confirmation | `[OK]` |
| `✗` | Fatal error | `[FAIL]` |
| `⚠` | Non-fatal warning | `[WARN]` |
| `➜` | Next-step / info pointer | `->` |

**Color/style degrade rule:** All bold/dim/color styling AND the Unicode symbols above must be skipped in favor of plain text (using the ASCII fallback column) whenever `process.stdout.isTTY` is `false` (piped/redirected output) **or** the `NO_COLOR` environment variable is set (per the [no-color.org](https://no-color.org) convention). This is a behavioral default, not a new CLI flag — Commander's locked flag set (`--port`, `--no-open`, `--scan`) is unchanged.

---

## Color (terminal ANSI semantics)

| Role | Value | Usage |
|------|-------|-------|
| Success | green (ANSI `32`) | `✓` symbol + "server running"/"port released" confirmations |
| Error | red (ANSI `31`) | `✗` symbol + fatal startup errors (EADDRINUSE, unexpected bind failure) |
| Warning | yellow (ANSI `33`) | `⚠` symbol + non-fatal warnings ("shutting down…", snapshot-recording failure) |
| Accent (10% — reserved) | cyan (ANSI `36`), bold | **Reserved exclusively for the printed connectable URL string** — the `➜ Local: http://127.0.0.1:<port>/?t=<token>` line, in both the launch banner and the manual browser-open fallback message |
| Default/dim | terminal default / dim (ANSI `2`) | Body and hint text — the "60/30" dominant surface equivalent, since a terminal has no background-color control |
| Destructive | not applicable | No destructive actions occur via CLI in this phase (revert/delete confirmations are Phase 5 UI scope) |

Accent reserved for: **the printed URL only** — never applied to any other line, symbol, or word. This keeps the one truly actionable string in every message visually unambiguous.

## Copywriting Contract

Exact CLI message copy for this phase's five required surfaces (launch banner, "server running" line, port-in-use/error messages, Ctrl-C shutdown confirmation, browser-open fallback) plus the two additional messages the locked decisions (D-03, D-12) require:

| Element | Copy |
|---------|------|
| **Launch banner** (printed once, after successful bind) | `GSD Config Manager` *(bold)* — blank line — `  ➜  Local:   http://127.0.0.1:<port>/?t=<token>` *(URL bold+cyan)* — `  ➜  Press Ctrl+C to stop` *(dim)* |
| **Primary next-step line** (CLI equivalent of a primary CTA — the single most important line of output) | The banner's `➜  Local:   <url>` line itself — this is the one line the user must act on (open it, or confirm it opened) |
| **Browser-open fallback — `--no-open` passed** | `  ➜  Browser auto-open disabled (--no-open) — open the Local URL above to continue` *(dim)* |
| **Browser-open fallback — `open()` failed** (headless/WSL/no default browser) | `⚠  Could not open your browser automatically.` / `   Open this URL manually to continue: http://127.0.0.1:<port>/?t=<token>` *(URL bold+cyan)* |
| **Port-in-use error** (`--port <n>` explicitly passed and taken; EADDRINUSE) | `✗  Port <n> is already in use.` / `   Run again without --port for an automatically assigned free port, or choose a different --port <number>.` — exit code `1`, banner never prints |
| **Generic unexpected startup error** | `✗  GSD Config Manager failed to start: <error message>` — exit code `1` |
| **Ctrl-C shutdown confirmation** (SIGINT/SIGTERM, D-03/Pattern 5 — printed only after `await app.close()` resolves, never before, per Pitfall 2) | *(blank line)* / `⚠  Shutting down…` / `✓  Server stopped. Port released, no changes lost.` |
| **Snapshot-recording failure warning** (D-12 — non-fatal; save already committed) | `⚠  Saved successfully, but history was not recorded (<reason>). Your changes are safe; version history for this save is unavailable.` |
| **Destructive confirmation** | Not applicable — no destructive CLI actions exist in Phase 2 (revert/delete confirmations belong to Phase 5's UI) |

**Tone:** Plain, factual, no exclamation points, no jokes. Every error message states the problem first, then the next step (matches CLAUDE.md's data-safety-first posture and the "user's save always wins" instinct carried from Phase 1).

**Non-CLI note:** The security-rejection responses (403 on bad Host/Origin/token, per SEC-01/SEC-02) are JSON API responses (`{ ok: false, errors: [{ message }] }`), not CLI stdout — they are never printed to the terminal by this phase and have no copy contract here. Phase 3's UI is responsible for rendering any user-facing copy for those errors when it consumes the API.
