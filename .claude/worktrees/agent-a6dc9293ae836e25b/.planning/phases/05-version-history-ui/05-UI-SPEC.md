# Phase 05 — UI Design Contract

> Visual and interaction contract for the per-config snapshot History workspace. Generated by gsd-ui-researcher; verify with gsd-ui-checker before implementation.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — retain the established manual CSS-token system |
| Preset | not applicable |
| Component library | none; use existing project-owned accessible controls and dialog pattern |
| Icon library | existing inline SVG icon pattern; use familiar clock/history, chevron, restore, added/removed/changed glyphs with text labels |
| Font | Inter, `ui-sans-serif`, `system-ui`, `-apple-system`, `BlinkMacSystemFont`, sans-serif |

**Existing-token contract:** Reuse `--gsd-*` variables in `web/src/styles.css`; do not introduce Tailwind, shadcn, or a parallel theme. Preserve light/dark token parity. Reuse the existing button, empty-state, card, rail, pane, and dialog visual language.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Badge internals, icon-to-label gaps, tree indentation increments |
| sm | 8px | Timeline-row internals, inline metadata groups, compact controls |
| md | 16px | Default card padding, pane padding, normal vertical rhythm |
| lg | 24px | Workspace header and split-pane padding |
| xl | 32px | Major separation between summary and diff content |
| 2xl | 48px | Centered empty/loading/error-state vertical breathing room |
| 3xl | 64px | Reserved for full-page empty-state composition only |

**Exceptions:** Icon-only rail buttons and any icon-only expand/collapse or close controls have a minimum interactive target of 44 × 44px. Restore and draft-decision buttons use existing button sizing but never render below 44px high on touch-capable layouts.

## Typography

Use exactly these four sizes and two weights within new History UI. Preserve existing monospace fallback only for JSON paths and scalar values.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Metadata / label | 12px | 400 | 1.5 |
| Body / control | 14px | 400 | 1.5 |
| Section heading | 16px | 600 | 1.2 |
| Workspace heading | 20px | 600 | 1.2 |

- Snapshot sequence, exact timestamp, changed paths, JSON keys, and scalar values use the existing monospace stack at the role size.
- Relative time is supplemental metadata, never the sole timestamp; supply exact local date/time as visible secondary text or an accessible label.
- Long config names, paths, key paths, and scalar content must wrap at natural word boundaries; use `overflow-wrap: anywhere` for machine-generated paths. Do not truncate content needed to identify a restore target.

## Color

Use the established semantic tokens in both themes; do not hard-code a history-only palette.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--gsd-bg` (`#ffffff` light / `#0f172a` dark) | Main comparison canvas, expanded diff background, dialog base |
| Secondary (30%) | `--gsd-surface` and `--gsd-surface-elevated` (`#f8fafc` / `#ffffff` light; `#1e293b` / `#334155` dark) | Timeline pane, snapshot rows, summary cards, workspace header, sidebar continuity |
| Accent (10%) | `--gsd-accent` (`#2563eb` light / `#60a5fa` dark) | Selected snapshot row, keyboard focus ring, Back to editor action, expand controls, current selection outline, success-notice `View history` link/action |
| Destructive | `--gsd-danger` (`#dc2626` light / `#f87171` dark) | Final Restore button, restore-risk icon, blocking restore/validation failure only |

**Supporting semantic colors:** Use `--gsd-success` for completed-restore notice and `--gsd-warning` only for the existing non-blocking snapshot-recording warning. Diff semantics use destructive for removal, success for addition, and accent for modification, but every state also has a text label and icon; color never carries diff meaning alone.

Accent reserved for: selected snapshot state, focus states, Back to editor, tree expand/collapse affordances, current active selection, and `View history` from the post-restore notice. It is not a generic button or decoration color.

## History Workspace and Interaction Contract

### Entry, shell, and draft boundaries

- Provide an explicit `View history` action for the selected tracked config. Activating it enters a dedicated History workspace; it is not a chapter, route overlay, or drawer.
- Retain the tracked-config sidebar and its current selected-file state. Hide the chapter pane and global settings search while History is active; the main landmark label becomes `Version history`.
- The header contains: an eyebrow `Version history`, the selected config’s readable name, its path in secondary/wrapping text, a persistent `Current saved file` target label, and a secondary `Back to editor` button.
- Entering and leaving History preserves any unsaved editor draft unchanged. Every comparison explicitly says `Snapshot → Current saved file`; never call the target “current” without qualifying it as saved/on disk when a draft exists.
- If the user selects another tracked config from the retained sidebar, show that config’s own History workspace. Preserve the prior config’s draft in its draft owner; do not transfer it across configs.

### Layout and responsive behavior

- At widths above 900px, render a persistent two-column History body: a 280px snapshot timeline (`minmax(240px, 30%)`, max 320px) and a flexible comparison pane (`minmax(0, 1fr)`), separated by a 1px `--gsd-border` divider. Use a 24px body gap/padding.
- The timeline and comparison pane scroll independently beneath the workspace header. Keep the selected snapshot context and comparison actions sticky within their pane while the diff scrolls.
- At 900px and below, stack the timeline before the comparison pane. Timeline list receives a 16rem maximum height and its own scroll; comparison remains below it. Do not hide the selected snapshot or Restore action behind horizontal scrolling.
- At 768px and below, follow the established overlay behavior for the tracked-config sidebar. The chapter pane stays hidden in History; do not add a second history-specific navigation drawer.

### Snapshot timeline

- Order snapshots newest first. Group with `Today`, `Yesterday`, then a full local calendar date such as `Friday, July 17, 2026`; do not omit older groups.
- Each snapshot is a full-width selectable button with: relative time (for example `18 minutes ago`), exact local date/time, `Snapshot #<sequence>`, and an explicit computed change count (`1 key changed` / `4 keys changed` / `No key changes`). It contains no actor, message, or invented save label.
- Selection updates the adjacent comparison in place, sets a visible accent outline/subtle background, and exposes `aria-current="true"` or equivalent selected state. Initial selection is the newest snapshot after list/detail data is ready.
- Changed counts may load after metadata. Until resolved, show a neutral `Calculating changes…` label in the count slot rather than a misleading zero; retain row selection and restore availability only after the selected comparison has loaded.
- For long timestamps/names and nested key paths, wrap metadata and key-path previews; snapshot rows must grow vertically rather than clip essential identity data.

### Comparison pane and structural diff

- The comparison header restates the selected snapshot exact local time and sequence, then shows `Snapshot → Current saved file`. It includes a secondary `Restore this snapshot` action; this is the phase’s primary CTA.
- Render a concise summary before the tree: three labeled counts (`Added`, `Removed`, `Changed`) and an exhaustive, wrapped list of changed key paths. Count labels must use correct zero/singular/plural grammar. If there are no semantic changes, state `This snapshot matches the current saved file.`
- Render the complete structural diff below the summary. Include every changed node plus enough parent branch context to orient it. Changed branches are expanded initially; unchanged sibling branches are collapsed initially and have explicit `Expand unchanged` / `Collapse unchanged` controls.
- Display scalar and short values as `before → current`; use titled, expanded preformatted blocks for long strings, arrays, or nested objects. Preserve structural semantics for arrays rather than presenting a line-based JSON diff.
- Each changed leaf includes a text state (`Added`, `Removed`, or `Changed`) and a state icon in addition to its semantic color. Added means present in Current but absent in Snapshot; removed means present in Snapshot but absent in Current.
- Before summary creation or tree rendering, apply the established descriptor-driven sensitive-field projection to both documents. Masked content uses a fixed opaque marker (for example `••••••`) and no reveal control in History. Never leak sensitive values through inline diffs, counts, key previews, dialog copy, error messages, or diagnostics.
- Use `json-diff-kit` for structural comparison only. Use a project-owned accessible tree renderer so expansion state, changed-branch context, keyboard controls, and redaction guarantees remain under project control.

### Restore confirmation and outcomes

- `Restore this snapshot` opens an alert-style confirmation dialog; it never writes immediately. The dialog names the config and exact selected snapshot time, repeats the added/removed/changed summary, and says: `Your current saved file will be saved as a new snapshot before this restore, so you can undo it.`
- Dialog actions are `Cancel` (secondary, initially focused), `Restore snapshot` (danger), and no typed confirmation. Escape cancels; focus is trapped while open and returns to the invoking Restore button on close. Disable the final action and announce `Restoring snapshot…` while the mutation is pending.
- If a dirty draft exists when final restore is requested, replace the final confirmation step with a draft-decision dialog: explain that History compares saved content and the draft cannot remain after restoring. Offer exactly `Save draft first`, `Discard draft and restore`, and `Cancel`. Initial focus is `Cancel`. `Save draft first` completes the ordinary save, refreshes comparison/history, then requires the user to review and confirm restore again; it does not restore automatically.
- On successful restore: close dialogs; reload the config from the server; clear stale draft state; refresh history and comparison queries; return to the normal editor; show a persistent success notice, `Restored the snapshot from <exact local timestamp>.`, with `View history` action.
- On a validation or atomic-write failure: remain in History with the selected snapshot and loaded diff intact. Show `Couldn’t restore this snapshot. Your config was not changed. <actionable server-safe reason> Try again or return to the editor.` in the blocking error treatment. Keep Restore available after the request finishes.
- On a non-blocking history-recording warning after a successful restore: return to the editor and show the same warning presentation used after normal saves; it must say the config was restored but the recovery snapshot may not have been recorded.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | `Restore this snapshot` |
| Entry action | `View history` |
| Back action | `Back to editor` |
| Empty state heading | `No saved versions yet` |
| Empty state body | `History starts after you change and successfully save this existing config. Your current file is not shown as a restorable version.` Actions: `Back to editor`. |
| Loading state | `Loading saved versions…` for the timeline; `Loading comparison…` for the selected diff. Use skeleton rows/tree lines without fabricated data. |
| Detail-load error | `We couldn’t load this comparison. Your config was not changed. Try again, or choose another saved version.` Include `Try again`. |
| Restore blocking error | `Couldn’t restore this snapshot. Your config was not changed. {safe actionable reason} Try again or return to the editor.` |
| Restore success | `Restored the snapshot from {exact local timestamp}.` Action: `View history`. |
| Non-blocking warning | `Your config was restored, but we couldn’t record its recovery snapshot. Your restored file is safe; check the warning and save again when ready.` |
| Destructive confirmation | `Restore snapshot`: `Restore the saved version from {exact local timestamp}? Your current saved file will be saved as a new snapshot first, so you can undo this restore.` Final action: `Restore snapshot`. |
| Dirty-draft confirmation | `You have unsaved changes. Save them first, discard them and restore the saved version, or cancel.` Actions exactly: `Save draft first`, `Discard draft and restore`, `Cancel`. |

## Accessibility Contract

- Use semantic landmarks: retained `Tracked configurations` sidebar, main `Version history` landmark, timeline as a labeled navigation/list region, and comparison as a labeled content region.
- Snapshot rows are keyboard-operable buttons; Arrow-key navigation is optional, but Tab/Shift+Tab, Enter, Space, visible `:focus-visible`, and selected-state announcement are mandatory.
- Diff-tree expand/collapse controls are native buttons with `aria-expanded` and a programmatic name naming their branch. Tree rows expose text state in addition to decorative icons.
- Restore/draft dialogs implement modal alert-dialog behavior: `aria-modal`, labelled/described relationships, focus trap, Escape cancel, least-destructive initial focus, inert/unreachable background, and focus return.
- Meet at least 4.5:1 contrast for text and controls against their token backgrounds in both supported color schemes. Never rely on color alone for diff state, warning, error, or selection.
- Respect `prefers-reduced-motion`; use no required motion to communicate state and keep transitions at or below the existing 150ms token pattern.
